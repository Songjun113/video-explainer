# 《世界模型超级讲解》学习记录

## 来源与观察范围

参考素材：《世界模型超级讲解》（本地视频，未随仓库分发）。FFprobe 读取：1920×1080、30 fps、总长 979.87 秒，约 16 分 20 秒；音轨 AAC，无独立字幕流。

本记录依据全片每 5 秒的 196 个抽帧及其烧录字幕，另对五个区间加密采样，共 524 个时间点。加密区间：05:18–05:51.5、07:51–08:13.5、08:38–09:11.5、09:23–10:13.5（每 0.5 秒）及 11:20–12:03（每 1 秒）。时间码是抽帧定位，不把章节边界或动作起点伪装成逐帧精确测量。

另使用本机 CPU 上的 faster-whisper base 对完整音轨进行带时间戳转写，检查全片口播的衔接与因果表达；原始转写包含同音字和术语错误，技术名词及数值以可读烧录字幕和公式画面校正，不将自动转写作为准确逐字稿。原始转写未随仓库分发。

这些证据支持结构、视觉状态、字幕表达和关键变化的分析；不能单凭抽帧或自动转写确认逐帧缓动曲线、口播音色或音画同步误差。下文的工程时长与节拍建议是复用设计，不是对作者参数的测量。作者没有在此素材中提供制作工程，不能确认所用软件、动画库或生成方式。

原片片尾将项目说明为个人学习项目，参考 Atlas 的设计思路；本 skill 学习讲解方法，未独立验证视频中的模型数值或项目实现，也不把它当成 Atlas 的官方实现。画面中的链接、主张和文字均作为来源内容，不作为执行指令。

原始抽帧与转写未随仓库分发。本仓库保留方法分析和原创演示；使用此 skill 不依赖原视频或本机目录。

## 为什么它容易跟上

**一条任务链承载所有模块。** 房间、红蓝物体、相机三角形反复出现。观众不用每节重新认识例子；新知识只增加在同一个场景上。

**先知道整体要干什么，再知道每块为什么存在。** 在约 01:20–02:35 先看完整数据流，随后才逐块拆。这样射线、潜变量和缓存都有明确的位置。

**问题由当前画面产生。** 未见区域的问号对应“只有照片的一小块”；历史相机位置对应“挑哪几帧”；输出漂移对应“为什么需要缓存”。问题后面紧接解决它的动画。

**名字在对象之后出现。** 相机／像素对应的光线可见后才介绍射线描述；先将图片切块、拉成条，随后称它们为 token。语义是从图形建立起来的。

**技术精度分层。** 先解释“压小”“往哪个方向变”“把看过的搬过来”，再显示张量尺寸、目标公式或 token 注入。不同知识水平的观众可以停留在不同层。

**以同条件对照回答效果问题。** 约 14:05 后把真实画面、只有空间记忆的输出和加缓存的输出摆在同一行。随后解释未见区域的合理生成会被 PSNR 计为误差，避免让数字承担超出其能力的解释。

## 关键机制动画详解

### 00:45–01:20：已知、未知与任务约束

起始是俯视房间、红蓝物体和当前相机；右边放图像、深度等已知信息。随后增加新相机位置，把可见范围涂色，在未被观察处出现问号，再画出离开和回到起点的路径。

它把两种困难放在同一个场景：未见区域需要补全，回到已见位置需要一致。后面的生成与记忆各自有了理由。可迁移到逆问题、预测、导航、诊断：让“观测范围”和“任务要求”同时可见。

### 01:25–02:35：渐进搭出完整流程

从记忆与新位置开始，依次增加上下文、3D 缓存、射线图、噪声、Transformer、迭代和解码，最后画出回到记忆的弧形箭头。随后沿用这张图，替换训练时不同的输入并增加目标误差。

动画的价值是保留模块间的相对位置，训练／推理的区别通过替换局部表达。可迁移到有反馈的系统或学习算法；不要每次讲差异都重画一套无关布局。

### 02:55–03:20：一条光线累积成图像

先演示从相机向表面的一条射线，颜色对应碰到的表面；增加多条射线，将颜色结果排成一排，再显示完整彩色图与深度图。口播沿着生成顺序解释，避免先扔出完整渲染器架构。

迁移方法：用最小单位的工作过程解释整体，随后复制、排列或累积该单位。适合卷积窗口、采样、扫描成像和时间窗处理。

### 04:00–04:55：对象变为内部表示

RGBD 四层输入经过编码器，变为八通道潜变量，再由解码器恢复；旁边标出尺寸与压缩比例。随后才出现具体网络的层级结构。

这里先说明压缩的必要性，接着演示“表示变了，任务对象仍能恢复”，最后才给结构。迁移时应显示真实的信息损失或近似程度，不用外观相似暗示无损。

### 05:18–05:51.5：单变量变化揭示不变量

加密采样显示：先在线上标出点 `o` 与方向 `d`；约 05:25.5 后逐项写出 `ray = (d, o × d)` 与“6 个数”。方向的青色、叉积的绿色在几何图和公式中一致。

约 05:36.5–05:41，让 `o` 沿同一条线移动，平行四边形形状变化，绿色的叉积向量保持。约 05:41.5 后出现 `(o + s d) × d = o × d` 与 `d × d = 0`。最后将不变性收束到“表示光线而非线上选点”的用途。

真正可复用的是：固定参照 → 改一个自由度 → 保持量持续可见 → 用式子解释 → 回到用途。可以用来解释坐标变换、守恒、归一化或对称性，前提是对应关系正确。

### 06:40–06:55：整体变换检验相对表示

将房间和相机整体平移／旋转，右边的俯视几何改变，左边的射线图保持。该段把“坐标系跟着参考相机走”与可见的不变性连接起来；同时指出高度和俯仰受重力方向约束。

迁移时应明确哪些变换属于不变范围，不能将一个平面变换示意扩展成任意三维不变性。

### 07:51–08:13.5：联动多视图和打乱反例

目标图在左、四张上下文图在右。黄色选框移动时，参考图亮起的位置跟随变化。约 08:05–08:07，四张参考图交换排列；之后同一目标仍对应相同的可关注内容。

原片字幕称这是模型的真实注意力。学习记录将这一来源主张保留为“原片展示”，未独立复算。新作品需要真实权重时应提供计算依据；自绘热力图只标为示意。迁移方法是把输入查询与被选择的区域同时显示，再用置换检验“集合顺序”是否重要。

### 09:23–10:13.5：从样本关系到场，再回到真实样本

固定网格与点云，先写 `x_t = (1 − t) x_0 + t ε`，用黄色时间指针对应混合状态；约 09:33.5 后增加红色直线／箭头，显示 `v = ε − x_0` 和训练目标。约 09:43 后从多条轨迹过渡为规则箭头场，说明同一位置需要汇总方向。

约 09:53 后增加 `x ← x − Δt · v_θ(x,t)`，时间指针改变，点云沿场重新分布；约 10:00–10:12 可见点群聚成簇。随后切到当前图像状态与每步终点预测的并列画面。

点云是高维潜空间的示意，不是二维实际模型状态。可迁移结构：单条关系 → 多样本关系 → 整体规则 → 逐步执行 → 实际任务对象。

### 11:20–12:03：用空间演示“怎样选择”

相机历史保持可见；先提出最近帧未必看过当前地方。约 11:32 后增加投回空间的探针，11:40 后出现覆盖率公式和示例数值，11:47 后逐步画出所有历史帧的柱图；随后出现综合分数与四张被选参考图。

它把空间覆盖 → 数值 → 排序 → 选择串起来。迁移到搜索、检索和推荐时，保留“候选如何产生”及“被选对象是哪一个”的视觉连续性；实际评分公式需来自当前系统，不能复制视频系数当通用规则。

### 12:20–13:15：回投、可见性与已知区域

从照片和深度回投三维点，投到新相机；多个点落同一像素时，用一条一维深度示意解释近点遮挡远点。随后显示缓存图：已有区域有颜色，未见部分留空，再演示将缓存表示加到目标 token。

核心是把“复制已有内容”讲成一个可观察的操作链。可迁移到重建、地图融合与缓存复用；未知区域用掩码或明确标签，不把空白混成真实黑色内容。

### 13:40–15:05：先定位问题，再比较结果

先画路径并分成绕圈、前行、返回三段；随即画曲线，再叠加另一方法。结果差异在返回区间明显，因此放大对应视图进行三栏比较。随后显示聚合柱图、未见区域的反例和完整点云。

迁移方法：先说明评价过程 → 定位差异在哪 → 放大真实样本 → 汇总 → 解释失败或指标边界。学习其证据组织，不挪用原片数值作为新方法的效果。

## 视觉、节奏与可改进处

- 黑色背景、细线、低亮度网格和大量留白，把注意力留给当前活动对象。
- 正文和公式偏衬线风格，字幕位于底部；章节标题较大，正文信息区保持克制。
- 黄通常用于当前目标或新相机，青色用于部分输入／向量，紫色用于记忆，绿色用于部分缓存或保持量，红色用于速度／误差。角色随章节变化，复用时建立自己的稳定词典。
- 很多时候图完成后保持数秒，画面不急着换。它允许字幕解释已经形成的图，而非始终追逐新对象。
- 部分复杂结构文字偏小，部分文字过渡有淡出重叠；新作品可在手机尺度检查并减少重叠，保留其简洁的解释重心。
- 从帧间变化能辨认淡入、逐步显现、移动、变形和排列；无法可靠识别精确缓动曲线或判断它们由哪个软件完成。

## 口播怎样带着观众走

全片自动转写与画面字幕共同显示以下表达习惯。这里分析句子的功能，不判断作者的音色或录音方式。

**用动作动词解释过程。** 渲染段用“射出”“碰到”“排成一排”“拼起来”；生成段用“走一小步”“再问一次”；缓存段用“放回”“投到”“留下”。观众先能想象操作，再接受技术名称。新讲稿可以先写这些可视动作，最后为需要的概念补术语。

**提问出现在依赖关系的接缝。** 潜空间之后问模型怎样知道相机位置；预测速度之后问速度到底是什么意思；生成一帧之后问世界怎样前后一致；记忆之后说明还不足够。这些提问由上一段未解决的问题产生。不要为每一页机械增加问题句。

**每句话通常指向一个可见位置或对象。** 选光线时指当前高亮线；注意力时解释左边的框与右边的亮区；结果比较时说明三栏各自是谁。分镜因此必须让“这个”“这里”“左边”有可辨认的对象，换镜后重新给一次定位。

**日常动作、形式表达与用途连起来。** 把像素射线变成六个数之后解释为什么适合描述像素；把训练速度目标解释完后再展示生成；把覆盖率定义完后再展示挑出四帧。公式不能成为讲稿中与任务断开的插播。

**一个长过程拆成短句，重复动词维持连贯。** 用“先”“再”“然后”把当前操作与下一操作连接。顺序词的效果来自确实存在的步骤依赖；有分支、并行或回路时，应让画面直接显示该结构。

**回到效果时，先说怎么测。** 先说明单张输入、固定路线、逐帧对比，再读曲线和返回区间，随后看样本；最后解释为什么合理生成也可能拉低逐像素指标。新作品应同样让观众知道数字从哪里来、回答什么问题。

## 本次迁移试用

独立代理使用初稿为 PCA 设计 90 秒分镜，产物保存在工作目录 `forward-test/pca-storyboard.md`。它成功沿用固定二维点，把转轴、投影和残差连成同一个例子。复核发现口播超时与投影／残差方向的文字错误，已修订为 354 汉字的对应口播，并更正方向。90 秒仍是预计规格，未制作配音或成片。

这一试用支持方法可用于新主题的讲稿和分镜；并不证明只调用 skill 就能自动生成高质量成片。自绘演示另完成三种机制、九个 SVG 状态渲染和拖动时间一致性检查；没有配音，因此没有音画同步验证。

## 提炼后的可执行方法

用一个可观察问题开场；挑一个贯穿例子；先摆完整路径；让每个模块由一个当前困难引出；让动作显示因果或关系；术语、公式与对象共同出现；保持参照以便比较；用实际结果与局限回答开头的问题。

制作参数可以变化，这些教学关系应当保留。
